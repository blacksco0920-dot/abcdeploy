## ADDED Requirements

### Requirement: 已实现路径必须具有跨层验证矩阵
项目 MUST 为本地文件夹到本机、Linux 服务器、更新部署和版本恢复分别维护可追溯的验证场景，并将 Feature、Tauri/application、Workspace、Provider/领域测试关联到对应用户路径。

#### Scenario: 审查本机运行闭环
- **WHEN** 本机运行进入验证阶段
- **THEN** 验证矩阵覆盖最终源码快照、受管运行目录、启动、连续成功证据、访问地址和重启恢复

#### Scenario: 审查服务器上线闭环
- **WHEN** 服务器上线进入验证阶段
- **THEN** 验证矩阵覆盖来源身份、环境准备、构建与不可变版本、远端运行、公网证据和首页/详情恢复

### Requirement: 成功必须来自完整且连续的运行证据
任何自动或人工闭环验证 MUST NOT 以命令退出、构建完成或容器启动单独判定成功；成功 MUST 包含匹配的源码/版本、实际运行、必要服务和访问端点证据，并满足产品合同规定的连续检查门槛。

#### Scenario: 检查结果尚未达到连续门槛
- **WHEN** 服务只通过一次检查或检查间隔与总窗口不足
- **THEN** 验证不得记录“运行成功”或“上线成功”

#### Scenario: 公网访问失败但服务仍运行
- **WHEN** 服务器内部运行证据通过而必要公网地址失败
- **THEN** 系统保留运行版本事实并进入访问验证恢复路径，不重新构建同一版本或宣称上线成功

### Requirement: 更新和恢复必须保护当前在线版本
更新部署和版本恢复 MUST 创建新的运行事实，并且 MUST 只在目标版本验证成功后原子更新当前在线指针；任何准备、部署或验证失败 MUST 保留此前在线版本。

#### Scenario: 更新没有源码变化
- **WHEN** 更新前重新解析的最终源码身份与当前在线版本一致
- **THEN** 系统返回无操作结果且不创建新的部署运行

#### Scenario: 更新或恢复失败
- **WHEN** 新版本或历史版本未通过完整验证
- **THEN** 系统记录失败尝试并继续投影此前已验证的在线版本

#### Scenario: 历史版本恢复成功
- **WHEN** 同一项目与服务器的可取得不可变历史版本重新部署并验证成功
- **THEN** 系统创建新的恢复运行记录并将当前指针切换到该新记录，而不改写原历史记录

### Requirement: 自动验证与真实客户端验收必须分开记录
项目 MUST 把自动测试、构建产物和真实客户端用户验收作为不同证据记录；自动门禁通过 MUST NOT 单独把能力状态升级为 `VERIFIED`。

#### Scenario: 自动矩阵全部通过但用户尚未验收
- **WHEN** 本机、更新或恢复的自动测试和构建均通过但没有用户真实客户端反馈
- **THEN** `docs/current-state.md` 继续将相应能力标记为 `IMPLEMENTED_UNVERIFIED`

#### Scenario: 用户完成真实客户端验收
- **WHEN** 用户明确确认某条验收脚本在签名 `.app` 与真实环境中通过
- **THEN** 项目记录日期、场景与结果，并只升级该条得到确认的能力状态

### Requirement: 本地验收产物不得触发正式发布
本 change MUST 使用当前 macOS Apple Silicon 的签名 `.app` 作为本地验收产物，MUST NOT 修改版本号、生成 DMG、创建或推送标签、触发 Release、构建全平台安装包或更新官网分发。

#### Scenario: 自动验证完成
- **WHEN** 所有代码与项目门禁通过并准备用户验收
- **THEN** 系统运行 `pnpm tauri:build:app`，报告 `.app` 路径与签名结果，并保持正式发布资产不变
