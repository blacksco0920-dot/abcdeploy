## 1. 建立路径验证矩阵

- [ ] 1.1 在前两个 change 归档后的代码基线上，把本机、服务器、更新和恢复映射到 Feature、Tauri/application、Workspace、Provider/领域测试与人工验收场景
- [ ] 1.2 逐项标记现有自动证据、缺失证据、真实环境前置条件和当前 `VERIFIED`/`IMPLEMENTED_UNVERIFIED` 状态
- [ ] 1.3 为矩阵中每个缺口选择最小跨层测试入口，不复制生产状态推导或连接个人生产账号

## 2. 验证本机运行闭环

- [ ] 2.1 补齐最终源码快照、受管运行目录、启动与本机访问地址的跨层回归测试
- [ ] 2.2 补齐连续三轮证据、失败后重新计数、五分钟新鲜度和重启恢复测试
- [ ] 2.3 对发现的本机路径缺陷先添加失败测试再修复，并运行本机相关 Rust 与 React 测试

## 3. 验证服务器上线闭环

- [ ] 3.1 复核来源身份、服务器环境准备、构建、不可变版本、远端运行和公网证据的跨层测试
- [ ] 3.2 补齐内部服务成功但公网失败、只恢复验证而不重建，以及首页/详情恢复当前结果的测试
- [ ] 3.3 对发现的服务器路径缺陷先添加失败测试再修复，并保持已有真实服务器验收记录不被自动结果改写

## 4. 验证更新与版本恢复

- [ ] 4.1 补齐源码无变化不创建运行、源码变化创建新尝试和更新成功后切换当前版本的测试
- [ ] 4.2 补齐更新失败仍投影旧在线版本、历史版本资格校验和恢复失败不移动指针的测试
- [ ] 4.3 补齐恢复成功创建新运行记录、保留原记录并原子切换当前指针的跨层测试

## 5. 自动门禁与本地测试包

- [ ] 5.1 运行 `pnpm check:project`、`pnpm check:secrets`、验证矩阵受影响测试和完整 `pnpm check`
- [ ] 5.2 生成验证报告，逐条关联测试命令、结果、未验证外部事实和禁止升级的状态
- [ ] 5.3 运行 `pnpm tauri:build:app`，核对 macOS Apple Silicon `.app` 路径、稳定 Apple Development 签名与可启动性
- [ ] 5.4 确认版本号、标签、Release、DMG、全平台安装包和官网分发资产均未改变

## 6. 真实客户端验收与状态落账

- [ ] 6.1 为本机运行、服务器回归、更新和恢复提供短而可重复的 `.app` 验收脚本，说明每步预期事实与失败后的保留状态
- [ ] 6.2 等待用户逐项确认真实客户端结果，不用自动通过或无反馈替代验收
- [ ] 6.3 仅将用户明确通过的能力及日期更新到 `docs/current-state.md`，其余能力继续保持 `IMPLEMENTED_UNVERIFIED` 或 `TARGET`
- [ ] 6.4 同步实现证据索引与 CodeGraph，并再次运行项目质量与密钥检查
