# ABCDeploy MVP 实施与验收

## 1. 完成定义

本轮只有在以下事实全部成立时才算完成：

- 用户可以选择本地文件夹或代码仓库地址；
- 用户可以选择这台电脑或某台服务器作为运行位置；
- 四种来源与运行位置组合都能进入同一套自动检查；
- 所有必须由用户处理的阻塞项一次形成完整待办列表；
- 全部待办经系统验证通过后，运行/上线主按钮才可用；
- 执行结束后还要独立验证源码、实际运行版本、服务健康和访问结果；
- 证据不完整时不显示运行成功或上线成功；
- 页面遵循当前前端规范，只保留部署列表和单页部署编辑器。

## 2. 页面验收

### 2.1 我的部署

- [ ] 首页只有部署列表和 `新建部署` 主操作，不预放搜索。
- [ ] 每条记录明确展示项目、运行位置、当前事实、可用地址和最近验证时间。
- [ ] 本地来源标题默认取根文件夹名，仓库来源标题默认取去掉 `.git` 的仓库名；新建部署不要求额外填写名称。
- [ ] 系统不根据项目内容猜测业务名称；可选重命名只改变显示名称，不改变来源、部署和更新身份。
- [ ] 未验证成功的部署不使用绿色成功状态，不伪造访问地址。
- [ ] 首页只出现产品合同定义的列表信息和 `新建部署` 主操作。
- [ ] 部署成功后首页立即显示同一持久化结果；再次打开直接恢复结果和地址，不重新要求选择服务器或创建任务。
- [ ] 较新的更新失败不抹掉仍在线的上次成功结果，列表同时说明当前在线事实和更新失败。

### 2.2 新建或编辑部署

- [ ] 使用一个自然纵向页面，不建立第二套导航或编辑结构。
- [ ] 页面依次展示项目来源、运行位置、完整待办和唯一主操作/结果区域。
- [ ] 未选择项目时运行位置区域不可执行，并解释为什么。
- [ ] 修改项目或运行位置后，受影响的检查 revision 和成功证据立即失效并重新验证。
- [ ] 默认页面只使用项目、运行位置、待办、运行、上线、地址和结果等用户概念。
- [ ] 每屏最多一个视觉主按钮，禁用时就近说明缺少什么。

## 3. 项目来源验收

### 3.1 本地文件夹

- [ ] 使用系统文件夹选择器，不要求用户输入路径。
- [ ] 自动识别项目名、服务、启动方式、端口和配置声明。
- [ ] 选择时生成发现快照；运行前重新计算内容身份，有变化就失效旧检查并重扫。
- [ ] 任务只引用最终不可变快照；未提交修改不能被遗漏。
- [ ] 默认不改动、不删除和不移动用户源码。
- [ ] 依赖、构建缓存、生成配置和其他运行文件都写入 ABCDeploy 管理目录，不直接从源码目录产生写入。
- [ ] 项目不可读或缺少可运行结构时形成明确待办，不只抛出扫描错误。

### 3.2 代码仓库地址

- [ ] 空值或明显错误 URL 在输入框旁提示，不创建候选对象、不进入待办。
- [ ] 接受格式有效的 Git 仓库 URL，并识别公开仓库。
- [ ] 读取默认分支并锁定 Commit SHA，不能只保存“最新代码”；MVP 不提供分支选择。
- [ ] 私有仓库仅在确实需要时要求授权。
- [ ] 格式有效但仓库不可达、无访问权限、无法读取默认分支或内容不可运行时分别形成待办。
- [ ] 仓库拉取到 ABCDeploy 管理目录，不污染用户已有项目。
- [ ] 再次运行前重新解析默认分支；Commit 变化时使旧检查失效并生成新的最终快照。
- [ ] 候选读取成功前不能构造稳定 `ProjectSource`，任务不能引用候选对象。

## 4. 运行位置验收

### 4.1 这台电脑

- [ ] 本机是与服务器并列的一类运行位置，不要求用户选择额外运行阶段。
- [ ] 自动检查本机运行工具、端口、依赖、必要配置和访问地址。
- [ ] 系统能安全准备的运行条件自动处理，不列为用户待办。
- [ ] 主操作为 `在本机运行`，结果为 `运行成功`。

### 4.2 服务器

- [ ] 可以选择已验证服务器或连接新服务器。
- [ ] 新服务器表单由适配器字段声明生成，只要求当前连接方式确实必需的信息，不在通用页面写死协议、端口、身份或凭据类型。
- [ ] 适配器区分可自动验证的目标事实和必须由用户判断的身份歧义；只有后者形成确认待办。
- [ ] 临时凭据只存在进程内存，不序列化、不写系统密钥库，取消连接后立即清除。
- [ ] 在首次远端写入前完成无副作用校验、认证和能力探测；不受当前适配器支持时停止并说明原因。
- [ ] 只有可复用安全连接建立并再次验证成功后才保存稳定 `Connection`，随后清除临时凭据。
- [ ] 必要确认、支持性探测和可复用连接验证全部通过前，不构造稳定 `DeploymentEnvironment`。
- [ ] 运行环境、受管目录和访问路由能够幂等准备。
- [ ] 缺少运行工具时自动识别运行位置，同位置可信下载来源优先，探测失败后自动切换其他国内来源和官方来源。
- [ ] 下载来源必须通过完整性、系统版本、架构和所需能力验证；只写独立受管配置，不覆盖系统主配置、已有运行环境或项目版本存储。
- [ ] 未知服务、资源占用或既有路由无法安全合并时停止并形成明确问题，不静默接管。
- [ ] 连接服务器时不要求项目域名；临时访问地址由具体部署生成，不保存在可复用服务器连接中。
- [ ] 首次上线缺少内部线路记录时，唯一且有效的构建服务与版本仓库连接由系统自动复用并后台补齐，不跳转旧工作流，也不要求重复填写地址、账号或密码。
- [ ] 已有服务器部署的结果页提供低频 `部署设置` 入口；首页不出现该入口。
- [ ] `部署设置` 复用首次上线的连接选择与验证能力；维护模式打开后一次展示构建服务、版本仓库、运行服务器和访问地址四类只读摘要，不再进入第二层摘要。
- [ ] 维护模式只有一个 `修改部署设置` 入口；进入编辑后连续完成 `部署资源 → 访问地址` 两步，第 2 步返回时回到包含四类信息的总摘要，最终主动作是 `保存为下次上线设置`。
- [ ] `initial` 与 `settings` 模式的组件标题均固定为 `部署设置`；前者只展示缺少项和紧凑的已准备摘要，后者展示完整线路，不通过两套标题或页面制造两个功能。
- [ ] 保存部署设置只影响下一次更新，不创建部署任务、不触发构建，也不改变服务器当前运行版本。
- [ ] 存在多个有效连接时只在当前页面各选择一次；缺失或失效时明确指出是哪类连接，并保留项目和服务器选择。
- [ ] 首次没有可复用构建与版本存储连接时，在当前待办一次填写最小授权；验证成功后保存连接并自动回到同一轮检查，不跳转旧页面。
- [ ] 版本仓库授权验证不止检查登录成功，还要验证目标命名空间具有推送权限；旧连接复用到新项目前重新执行该检查，失败时直接打开更新授权入口，不先启动一次必然失败的构建。
- [ ] 首次授权同时收集安全配置保存位置；客户端生成项目专用文件名和内容，并在同一待办引导打开外部平台、复制、粘贴和确认保存。用户确认前不写入项目引用，不显示线路已就绪。
- [ ] 安全配置保存位置尚未创建时，先提供创建入口，创建后继续原待办；不要求重新填写已经验证通过的构建或版本仓库凭据。
- [ ] 授权秘密只进入系统密钥库；项目文件只保存仓库、版本仓库和命名空间等非秘密标识。
- [ ] Provider 需要在外部控制台配置运行秘密时，另列可操作待办；不能把本地令牌验证成功当成外部配置完成。
- [ ] 主操作为 `上线到服务器`。

### 4.3 已有部署、更新与恢复

- [ ] 打开已经成功上线的项目时默认恢复“当前在线”结果，不要求重新选择服务器或重新走首次上线。
- [ ] 详情页只有一个高频更新动作 `更新上线`；部署设置只放在更多菜单。
- [ ] 更新前重新读取并锁定源码快照；源码身份没有变化时明确提示已经是最新版本，不创建任务或记录。
- [ ] 更新自动复用已保存的部署设置，并在执行前重新验证；失败不替换当前在线版本。
- [ ] 上线记录以 `项目 + 服务器` 为维度，首次上线、更新、恢复和失败尝试全部追加记录且不可改写。
- [ ] 当前在线指针只在新版本完成服务器部署和外部验证后移动；失败记录明确显示“未影响线上”。
- [ ] 只有历史中验证成功且不可变运行版本仍可取得的记录显示 `恢复此版本`。
- [ ] 恢复会创建新的尝试和记录；恢复成功后才移动当前在线指针，失败时旧版本继续运行。
- [ ] MVP 以上线记录承担版本管理，不新增独立版本管理页面。
- [ ] 同一项目与服务器的首次上线、更新和恢复共用目标锁，不能并发改变线上状态。

## 5. 待办验收

- [ ] 项目和运行位置确定后自动开始检查，无需另找“准备”页面。
- [ ] 检查整体状态完整覆盖 `idle → scanning → blocked | ready | check_failed`。
- [ ] 所有必要检查器进入终态前始终是 `scanning`；待办暂时为 0 也不能启用主按钮。
- [ ] 每轮检查保存 revision；项目、内容、运行位置或相关配置变化后旧 revision 不能继续授权部署。
- [ ] 一次展示全部已知阻塞项、准确总数和已完成数量。
- [ ] 授权或身份确认解除信息屏障后开启新 revision 并完整重扫；新一轮一次展示新增的全部已知事项，不逐项冒出。
- [ ] 所有待办同时可以处理，不出现“等待前项”或串行解锁。
- [ ] 待办只包含必须由用户输入、授权、选择或在外部平台完成的事项。
- [ ] 准备工具、建立连接、初始化目录和检查端口等系统动作不伪装成用户待办。
- [ ] 自动动作失败进入 `check_failed`，展示 `系统准备失败`、已保留事实、重试和技术详情。
- [ ] 只有确认必须由用户完成的外部动作，才能从自动失败转换成用户待办。
- [ ] 每行说明事项、原因、状态和唯一处理入口。
- [ ] 状态只使用待处理、检查中、已完成、仍有问题。
- [ ] 用户提交后必须由系统验证；不能点击“我已完成”直接变绿。
- [ ] 一项处理完后留在原页面，列表自动刷新，不要求用户重新点击上线。
- [ ] 待办未全部通过时主按钮不可执行，并显示还差几项。
- [ ] 待办全部通过只表示可以开始，不表示部署成功。
- [ ] `ActionChecklist` 明确区分 `readiness` 与 `verification`；部署后的访问待办只恢复验证，不重新构建。

## 6. 部署任务验收

- [ ] 点击主按钮后先重新确认源码身份；内容有变化时回到扫描，未变化才固定最终快照、运行位置和配置。
- [ ] `DeploymentRun` 只引用稳定 `ProjectSource`、稳定 `DeploymentEnvironment` 和最终不可变快照。
- [ ] 重复点击不会创建并行重复任务。
- [ ] 运行过程展示当前阶段、已完成/总步骤、已运行时长、最近活动时间和是否可以关闭客户端。
- [ ] 运行过程把“生成运行版本”和“保存运行版本”分别映射到真实构建与上传阶段；上传失败后更新授权只恢复上传，已经生成的镜像不重复构建。
- [ ] 长任务持续读取后台持久化事实；超过 30 秒无新活动时说明正在等待远端，不把静态加载态伪装成实时进度。
- [ ] 任务运行中不渲染没有实际行为的“查看进度”按钮；当前页面直接展示进度，主操作区只显示不可点击的 `正在运行` / `正在上线` 状态。
- [ ] `查看部署详情` 至少能展示任务编号、构建编号、代码版本、制品数量、当前技术阶段和问题编号；Provider、命令和脱敏日志按需继续下钻。
- [ ] 后台进入成功、需要处理、失败或取消状态后立即终止加载态，同一页面展示持久化结果。
- [ ] 成功结果把主地址作为唯一 `打开网页` 动作；其他地址可逐项打开，逐服务运行版本默认折叠且可查看。
- [ ] 失败恢复卡位于技术详情之前，明确展示“发生了什么、已保留什么、下一步做什么、从哪一步继续”。
- [ ] 失败状态只有一个与原因匹配的主动作：通用服务器失败为 `检查服务器并继续`；缺少必要配置为 `补全运行配置`，保存后自动从失败阶段继续。
- [ ] 远端多行错误优先保留经过脱敏的稳定问题码行，不被最后一行退出噪声覆盖；未知命令文本不直接展示。
- [ ] 客户端关闭后重开恢复同一任务、当前尝试和已完成事实。
- [ ] 重试创建新尝试，不静默修改原任务输入。
- [ ] 更新服务器失败时明确说明原有版本是否仍在运行。
- [ ] 已生成的不可变版本可从失败阶段继续，不因 DNS/TLS 等后置问题重复构建。

## 7. 成功证据门禁

### 7.1 通用证据链

- [ ] 展示本次选择的源码身份：本地快照或仓库 Commit。
- [ ] 展示生成的运行版本或本地运行身份。
- [ ] 验证所选运行位置实际运行的是该版本/进程。
- [ ] 区分必要内部服务和公开服务；无法判断时形成“选择需要公开的服务”待办。
- [ ] 验证全部必要内部服务和依赖健康。
- [ ] 为每个公开服务生成独立 `AccessEndpoint`，指定一个主地址，并从用户访问视角逐一检查。
- [ ] 首页展示主地址及“另有 N 个地址”，结果区域展示全部公开地址。
- [ ] 每条证据记录预期、实际、检查位置和时间。
- [ ] 关键检查连续通过至少 3 次，相邻至少 5 秒、总窗口至少 10 秒后才能显示最终成功。
- [ ] 当前证据有效期为 5 分钟；过期显示 `上次验证通过 · 待复查`，不能保持绿色当前成功。
- [ ] 打开已有部署或客户端重启后自动复查；离线时只展示历史事实和检查时间。

### 7.2 本机运行证据

- [ ] 实际运行源码快照与选择一致。
- [ ] 必要进程或容器仍在运行。
- [ ] 必要端口真实监听，依赖可连接。
- [ ] 所有本机公开访问地址连续检查通过。
- [ ] 结果卡展示地址、快照、服务数量、端口、验证时间和连续次数。

### 7.3 服务器上线成功

- [ ] 源码身份与不可变版本可以追溯对应。
- [ ] 服务器实际运行身份与预期版本一致。
- [ ] 必要服务与依赖健康。
- [ ] 每个访问地址命中正确公开服务。
- [ ] 系统可以准备无需用户先购买域名的临时地址。
- [ ] 从服务器外部访问全部公开地址成功。
- [ ] 用户改为自有域名后才要求 DNS、TLS 和证书通过。
- [ ] 结果卡展示地址、源码、实际版本、服务器、健康、访问结果和验证时间。

服务已运行但公网失败时：

- [ ] 不显示 `上线成功`；
- [ ] 显示 `服务已运行，访问地址仍需处理`；
- [ ] 保留已成立的版本和服务事实；
- [ ] 把公网问题重新加入待办；
- [ ] 修复后从访问检查继续，不重新构建。

### 7.4 业务验证边界

- [ ] MVP 只接受至少包含一个 HTTP 可访问服务的项目。
- [ ] 纯 CLI、Worker 或定时任务明确提示当前版本不支持，不伪造访问地址或成功证据。
- [ ] 没有健康接口或冒烟检查时，只宣称服务运行和地址可访问。
- [ ] 项目明确声明业务探针且验证通过后，才显示 `业务验证通过`。
- [ ] 不能用首页 HTTP 200 推导登录、支付或数据处理功能正常。

## 8. 四种组合场景

| 编号 | 项目来源   | 运行位置 | 关键验收                                                 |
| ---- | ---------- | -------- | -------------------------------------------------------- |
| S01  | 本地文件夹 | 这台电脑 | 冻结当前文件内容，本机服务与地址连续验证                 |
| S02  | 代码仓库   | 这台电脑 | 锁定 Commit，隔离拉取，本机运行和访问验证                |
| S03  | 本地文件夹 | 服务器   | 本地快照生成不可变版本，服务器摘要和公网验证             |
| S04  | 代码仓库   | 服务器   | Commit、不可变运行版本、实际运行身份、健康和公网证据完整 |

每个场景都必须分别覆盖：

- 无待办直接开始；
- 缺少必要配置；
- 授权或连接缺失；
- 执行失败并恢复；
- 服务运行但访问失败；
- 客户端中途关闭后恢复；
- 完整成功证据。

## 9. 典型错误场景

| 场景                   | 页面必须说明                       | 恢复动作                                 |
| ---------------------- | ---------------------------------- | ---------------------------------------- |
| 仓库地址无效           | 无法读取哪个地址，尚未创建任务     | 修改地址后自动重查                       |
| 私有仓库未授权         | 需要访问该仓库，其他选择已保留     | 授权并验证                               |
| 必要配置缺值           | 来自项目声明的字段名和注释         | 保存后系统验证                           |
| 本机端口冲突           | 哪个项目服务需要该端口             | 自动选择或让用户确认替代端口             |
| 一次性凭据错误         | 服务器尚未保存，凭据未保留         | 重新输入                                 |
| 目标身份证据变化       | 连接身份与已保存记录不同           | 明确核验，不能自动接受                   |
| 运行环境或路由准备失败 | 系统准备失败在哪，已完成和保留什么 | 系统重试；只有确需外部操作时生成用户待办 |
| 构建失败               | 代码或构建问题，旧运行版本状态     | 查看面向开发 AI 的诊断信息               |
| 服务不健康             | 哪个服务未就绪，版本是否已部署     | 查看服务诊断并重试验证                   |
| DNS/TLS 未生效         | 服务是否运行、地址哪一项未通过     | 修改外部配置后重新检查访问               |

错误文案必须回答“发生了什么、保留了什么、下一步做什么”。

## 10. 安全门禁

- [ ] Token 和可复用秘密正文只写系统密钥库，普通数据只保存秘密引用；一次性服务器凭据只在内存使用并及时清除。
- [ ] 错误、剪贴板内容和技术详情经过脱敏。
- [ ] 不同 Provider 凭据分别验证，不能暗示一个令牌覆盖全部平台。
- [ ] 远端最终身份使用适配器可验证的不可变身份，不使用会漂移的名称证明版本。
- [ ] 受管文件和路由修改先生成候选、验证、备份、原子替换，失败恢复。
- [ ] 所有用户可见成功都能查询到当前证据，不能由本地缓存猜测。

## 11. 实际客户端验收

MVP 直接在实际客户端和自动化测试中验收：

- 首页极简结构；
- 单页同时存在项目与运行位置选择；
- 单页结构且默认文案只使用用户概念；
- 四种来源与运行位置组合；
- 仓库 URL 字段校验和选择变化后的检查失效；
- `scanning/blocked/ready/check_failed` 整体门禁；
- 无用户待办时直接开始；
- 完整待办和按钮门禁；
- 新服务器动态字段、临时凭据生命周期和适配器声明的目标身份确认；
- 系统验证而非自我确认；
- 本机与服务器不同主操作；
- 任务进度；
- 成功证据；
- 证据过期后先复查、不能直接沿用绿色状态；
- 公网失败不宣称成功并能继续验证；
- 首页、编辑器和成功结果读取同一持久化事实，完成后不回到首次部署页。

历史 HTML 原型仍作为带有非权威提示的追溯资产保留，不能作为实现或验收依据；产品行为以实际客户端、产品合同和自动测试为准，是否删除历史资产必须由对应 change 明确决定。

## 12. 工程门禁

提交前至少执行：

```bash
pnpm check:project
pnpm check:secrets
git diff --check
```

修改生产代码时追加受影响的前端、Rust 和 Provider 测试；跨层修改运行完整：

```bash
pnpm --filter @abcdeploy/desktop lint
pnpm --filter @abcdeploy/desktop test
pnpm --filter @abcdeploy/desktop build
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

核心符号移动后运行 `pnpm codegraph:sync`；大规模结构变化运行 `pnpm codegraph:index`。

真实客户端功能完成并通过本地测试后，运行 `pnpm tauri:build:app` 生成 macOS Apple Silicon 验收包；这不等同于正式发布。
