# ABCDeploy 文档地图

`docs/` 的默认导航只包含当前有效定义。新会话默认只读 [当前状态](current-state.md)，再按任务的问题域选择权威材料；仍被保留的历史原型和 archived changes 不进入默认导航，也不参与当前事实裁决。

## 问题域权威

| 问题域 | 权威文档 | 何时读取 |
| --- | --- | --- |
| 已验收事实、未验证实现、下一步与禁区 | [当前状态](current-state.md) | 新会话默认入口。 |
| 用户最终应经历的规则 | [产品合同](product-contract.md) | 产品行为或用户体验发生冲突时。 |
| 代码怎样承载产品模型 | [工程架构](architecture.md) | 设计边界、分层、状态机或依赖方向时。 |
| 当前实现入口、调用链、测试起点、明确缺口与迁移债务 | [实现证据索引](internal/implementation-inventory.md) | 修改代码、迁移或定位影响范围时。 |
| 页面表达、验收与工程维护 | [前端规范](frontend-design-guidelines.md)、[实施验收](implementation-acceptance.md)、[工程质量规范](engineering-quality.md) | 任务直接涉及相应问题域时。 |

产品规则冲突以产品合同为准；实现边界冲突以工程架构为准；当前可用性与验收事实以当前状态为准。当前代码、自动测试、历史页面和原型不得反向改写产品合同。

## 有限阅读顺序

1. 先阅读 [当前状态](current-state.md)，确定当前事实和禁区。
2. 只按任务需要阅读上表对应的产品、架构或实现材料。
3. 修改代码时，再进入 [内部实施资料](internal/README.md) 查询 CodeGraph 和迁移细节；它不属于产品定义。

## 唯一产品模型

```text
选择项目  →  选择运行位置  →  处理完整待办  →  运行/上线  →  查看成功依据
```

项目来源只有两类：

- 电脑里的本地文件夹；
- 一个代码仓库地址。

运行位置只有两类：

- 这台电脑；
- 某台 Linux 服务器。

因此 MVP 必须覆盖四种组合：本地文件夹或代码仓库，分别运行到本机或服务器。

代码托管、构建、制品存储、远程连接、容器和路由都是实现细节。默认页面不要求用户认识它们。

## 部署列表标题规则

部署列表中的标题不是系统猜测的业务名称，也不是由构建服务或服务器返回的名称。它只表示这条部署记录对应的项目来源：

- 本地项目：默认取用户选择的根文件夹名称；
- 代码仓库：默认取仓库地址最后一段，并去掉 `.git` 后缀；
- 用户主动重命名后：使用用户填写的显示名称；
- 无法取得来源名称时：显示“未命名项目”。

这个标题只影响列表展示，不改变源码身份、部署记录身份、运行位置、访问地址或版本更新判断。同一个项目部署到不同位置时允许同名，由运行位置和地址区分。

## 五个核心对象

| 对象 | 回答的问题 |
| --- | --- |
| `ProjectSource` | 要运行哪份代码 |
| `DeploymentEnvironment` | 代码运行在哪里 |
| `ActionChecklist` | 当前还必须由用户处理什么，以及处理后从哪里继续 |
| `DeploymentRun` | 这一次实际执行到哪里 |
| `DeploymentEvidence` | 凭什么相信结果真的成功 |

待办全部完成只证明“可以开始”；命令完成、构建成功或内部阶段变绿也不等于最终成功。成功必须由源码身份、实际运行版本、服务健康和用户视角访问检查共同证明。

## 文档职责

- 产品合同写“用户最终应该经历什么”。
- 工程架构写“代码应该怎样承载产品模型”。
- 实现证据索引记录当前入口、调用链、测试起点、明确缺口与迁移债务。
- 前端规范写“页面怎样表达产品模型”。
- 实施验收写“用什么证据证明完成”。

这些文档不得互相冒充，也不得保留第二套并行产品定义。当前代码、迁移难度或既有页面不能反向修改产品合同。

## 维护规则

- 新结论直接修改当前文档，不新增日期型讨论稿或重复 PRD。
- 文档只描述通用产品，不写试点项目的账号、域名、密钥或业务字段。
- 默认删除已废弃资产并通过 Git 追溯；若 active change 明确保留历史资产，则只能放在“历史追溯”区并加显著非权威提示。
- 旧实现名词、具体 Provider 和兼容字段只能进入 `docs/internal/`；产品文档不得引用它们解释页面。
- 新增或移动核心符号后执行 `pnpm codegraph:sync`；大规模结构变化执行 `pnpm codegraph:index`。
- 提交前至少运行 `pnpm check:project`、`pnpm check:secrets` 和受影响测试。
- 目录、依赖、错误语义和完成定义必须遵守 [工程质量规范](engineering-quality.md)，不得用“先堆进去”换取短期速度。
- 未明确要求正式发布时，不升级版本、不生成 DMG、不触发远端发布。
