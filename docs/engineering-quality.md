# 工程质量规范

> 本文把“艺术级维护”转化为可以持续执行的工程约束。产品行为以 [产品合同](./product-contract.md) 为准，架构边界以 [工程架构](./architecture.md) 为准。

## 1. 维护目标

ABCDeploy 的代码应让第一次进入仓库的人能够快速回答四个问题：

1. 用户当前能完成什么；
2. 一次部署由哪些领域对象和用例组成；
3. 某个修改会影响哪些入口、状态和验证；
4. 哪些内容是生成物、兼容层或可以删除的历史资产。

简洁不等于把逻辑堆进少数大文件。高质量结构应同时做到：职责清楚、依赖单向、事实可验证、失败可恢复、历史可删除。

## 2. 单一产品主线

- 桌面客户端的唯一主线是“我的部署 → 新建或打开部署 → 完成待办 → 运行 → 查看证据”。
- 真实客户端和自动测试是唯一可执行产品参考，不维护与其并行的权威 HTML 原型；带有非权威提示且从默认导航隔离的历史原型可以按 change 的明确决定保留追溯。
- 用户概念只来自产品合同。Provider、容器、代理和远程执行细节默认留在系统动作或技术详情。
- 同一事实只保留一个权威来源。页面状态不得从按钮文案、局部缓存或旧任务记录反向猜测。

## 3. 目录与依赖边界

- `App.tsx` 只负责应用装配和页面切换。
- `features/` 按用户用例组织；一个 Feature 可以依赖类型化 API、通用 UI 和纯函数，不能让底层反向依赖页面。
- `api/` 只负责调用边界、兼容反序列化和错误归一化，不承载页面流程。
- Rust 命令层只校验边界并调用应用服务；仓储、Provider、文件、网络和密钥库分别归位。
- 跨层新增能力先确定领域对象和应用服务，再接 UI；不得直接向 `api.ts`、Tauri `lib.rs` 或 `workspace.rs` 追加整段业务流程。

依赖优先级：标准库 → 已有模块和 UI 基础组件 → 新依赖。新增依赖必须说明现有能力为什么不能覆盖，并删除被替代的依赖。

## 4. 文件预算

- 生产 TypeScript/TSX 默认不超过 800 行。
- 生产 Rust 默认不超过 1200 行。
- 测试文件默认不超过 1200 行。
- 现有超限文件属于显式迁移债务，只允许缩小，不能提高预算为新增代码让路。

当文件接近预算时，按领域职责拆分，不按“工具函数”“其他逻辑”这类模糊名称拆分。

## 5. 状态、错误与成功

- 用户可见成功必须来自当前可查询证据，不能来自任务已结束、缓存为绿色或按钮被点击。
- 错误必须回答：发生了什么、已保留什么、用户或系统下一步做什么。
- 系统能安全代办的动作自动完成；只有授权、秘密、外部确认和真实选择进入用户待办。
- 重试从失败步骤恢复，同一不可变源码和版本不得因为后置验证失败而重复构建。
- 所有秘密进入系统密钥库；日志、文档、前端快照和项目目录不得出现秘密正文。

## 6. 删除标准

以下内容应删除而不是继续兼容：

- 无法从当前入口到达且不是动态边界的运行代码；
- 已被真实页面接管且没有明确历史追溯职责的旧页面、旧画布和旧原型；
- 仅服务于已删除入口的组件、适配器、样式、测试和依赖；
- 已失效的阶段性记录和重复文档；历史结论由 Git 保存；
- 可重建的构建缓存不得被当成源码资产提交。

删除前使用 CodeGraph、文本引用和测试共同确认影响。Tauri 命令、序列化入口和脚本入口不能只凭“没有静态调用者”判断。

## 7. 文档层级

1. `docs/README.md`：文档入口与阅读顺序；
2. `docs/product-contract.md`：用户模型和产品不变量；
3. `docs/architecture.md`：领域、状态、应用服务和边界；
4. `docs/frontend-design-guidelines.md`：视觉和交互规范；
5. `docs/implementation-acceptance.md`：可验证验收门禁；
6. `docs/internal/`：当前工作树事实、迁移债务和工具说明。

核心文档不得包含具体 Provider 方案或历史产品模型。内部事实与核心合同冲突时，以核心合同为准并修正实现清单。

## 8. 每次修改的完成定义

1. 修改前阅读权威文档并查询 CodeGraph；
2. 先增加能够复现问题的测试；
3. 代码进入正确边界，没有新增不可达文件和禁用依赖；
4. 运行受影响测试、项目质量检查、秘密检查和差异检查；
5. 跨层修改运行完整前端与 Rust 门禁并同步 CodeGraph；
6. 本地功能验收通过后生成当前 macOS Apple Silicon `.app` 测试包；
7. 除非明确正式发布，不改版本号、不生成 DMG、不触发远端发布。

最低命令：

```bash
pnpm check:project
pnpm check:secrets
git diff --check
```

跨层修改追加：

```bash
pnpm --filter @abcdeploy/desktop lint
pnpm --filter @abcdeploy/desktop test
pnpm --filter @abcdeploy/desktop build
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
pnpm codegraph:index
```
