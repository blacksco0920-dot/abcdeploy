# ABCDeploy 当前实现清单

> 更新于 2026-07-26。本文只记录当前工作树事实和迁移债务，不定义产品。产品行为以 [产品合同](../product-contract.md) 为准。

## 1. 当前可执行主线

桌面端只有一条用户主线：

```text
我的部署
  → 选择本地文件夹或代码仓库
  → 选择这台电脑或服务器
  → 系统检查并列出完整待办
  → 运行或上线
  → 展示访问地址、源码身份、实际运行版本和验证结果
```

当前前端入口：

| 边界 | 入口 | 职责 |
| --- | --- | --- |
| 应用装配 | `App.tsx` | 首页与编辑器切换、当前项目身份 |
| 部署列表 | `ProjectGallery.tsx`、`features/deployment-list/` | 部署聚合、恢复、刷新与移除本地记录 |
| 部署编辑器 | `DeploymentEditorController.tsx` | 来源、运行位置、待办、任务和恢复编排 |
| 页面投影 | `DeploymentEditorPage.tsx` | 单页展示检查、运行进度、失败恢复和成功证据 |
| 类型化边界 | `api.ts`、`api/` | Tauri 调用、兼容反序列化和错误归一化 |

旧配置中心、旧工作区、四节点画布、运行配置独立页、FlowGram/Semi 依赖和 HTML 产品原型已经退出运行链路并删除。

## 2. 当前底层能力

Tauri 与部署内核继续提供：

- 本地项目发现、多服务识别、端口和必要配置解析；
- 不可变源码快照、任务、尝试、恢复点和成功证据持久化；
- 系统密钥库、连接复用和错误脱敏；
- 构建服务、版本仓库、Linux 服务器和公开访问地址适配；
- 服务器能力探测、受管连接准备、容器运行时和统一反向代理初始化；
- 运行配置恢复、服务启动、路由、DNS、TLS 和公网验证；
- 同一不可变版本恢复，不因后置验证失败重复构建。

具体 Provider 和兼容 Manifest 只属于适配层，不进入用户产品模型。

## 3. 持久化事实

本机工作区数据库保存项目身份、来源快照、运行位置、连接引用、任务、尝试、版本、服务、地址和验证证据。秘密正文只进入系统密钥库。

必须区分：

- 项目：用户想持续管理的应用；
- 部署：项目在某个运行位置的当前结果；
- 任务：一次准备或更新尝试；
- 版本：不可变源码和制品身份；
- 证据：当前结果是否真的可用。

首页和详情必须读取同一部署聚合，不能各自保存状态。

## 5. 删除边界

本轮已经删除：

- 无法从 `main.tsx` 到达的旧前端主线；
- 只服务旧主线的组件、测试、布局存储和 UI 依赖；
- 已被真实客户端替代的产品原型；
- 历史归档和重复阶段文档。

没有删除仍被当前执行链调用的 Provider、Tauri 命令、数据库兼容读取和部署内核。后续删除这些能力必须先完成动态入口、序列化、脚本和真实任务回归。

## 6. 体积说明

仓库目录的大部分磁盘占用来自 Rust `target/` 和前端 `node_modules/`，它们都是可重建缓存，不是业务代码。源码规模应按受版本控制文件、代码行数和运行可达性衡量，不能用整个工作目录大小代替。

`target/` 可以在需要释放磁盘时执行 `cargo clean`，但本地 `.app` 构建会重新生成所需产物。依赖缓存保留用于日常开发，不提交 Git。

## 7. 维护约束

- 新功能只进入产品合同对应的来源、运行位置、待办、任务或证据边界；
- 不恢复旧工作区、旧画布或 Provider 驱动的信息架构；
- 修改前使用 CodeGraph 查询定义、调用者和影响范围；
- 大规模删除和移动后重建 CodeGraph；
- 完成定义见 [工程质量规范](../engineering-quality.md)。
