# 在这台电脑运行

## 1. 定位

“这台电脑”是 MVP 中与服务器并列的一类运行位置，内部由 `DeploymentEnvironment` 承载。用户可以把本地文件夹或代码仓库直接运行在本机，不需要再选择额外运行阶段。

本机路径遵循同一主线：

```text
选择项目 → 选择这台电脑 → 自动检查 → 处理待办 → 在本机运行 → 查看成功依据
```

不再提供与主线分离的“本机运行模块”或额外运行准备页。

## 2. 两类项目来源

### 本地文件夹

- 读取用户选择的当前文件内容；
- 选择时生成发现快照，运行前重新读取；
- 内容变化时旧检查失效并重扫，最终冻结包含未提交修改的不可变快照；
- 不删除、移动或默认改写用户源码；
- 从 ABCDeploy 管理目录中的最终快照运行；依赖、构建缓存和生成物不写回用户源码目录。

### 代码仓库

- 校验仓库地址和授权；
- 读取默认分支并锁定 Commit；
- 拉取到 ABCDeploy 管理的隔离目录；
- 后续运行和证据都引用该 Commit，不使用模糊的“最新代码”。

再次运行前重新解析默认分支；Commit 变化时旧检查失效并重新生成最终快照。

## 3. 自动检查

系统自动检查：

- 项目服务与启动方式；
- 本机运行工具；
- 端口占用；
- 项目声明的运行依赖；
- 项目声明的必要配置；
- 进程或容器状态；
- 可访问地址。

安装可安全自动完成的工具、生成运行文件、启动受管依赖和探测端口属于系统动作，不列为用户待办。

只有必须由用户参与的事项才进入待办，例如：

- 私有仓库授权；
- 项目声明的必要配置缺值；
- 端口冲突且无法安全自动选择；
- 本机系统权限确实需要用户确认；
- 项目代码或依赖本身不可运行。

代码缺陷或开发依赖无法解决时，页面应明确建议用户回到开发工具处理，并提供可复制给开发 AI 的诊断信息。ABCDeploy 不假装已经修复项目代码。

## 4. 配置规则

- 配置来源以项目明确声明并由当前项目适配器支持的配置描述为准；具体文件格式不进入产品合同；
- 标题使用项目声明的说明，没有说明时显示原始 Key；
- 副标题显示原始 Key；
- 排序为缺失必填、已有必填、其他配置；
- 不硬编码某个试点项目的 API Key、管理员密码或业务枚举；
- 用户提交后由系统验证，不能直接标记完成；
- 敏感值只进入系统密钥库或受保护运行配置，不写普通日志和文档。

已保存的可复用配置存在明确且有效的匹配值时自动引用；多个候选无法判断时才让用户选择。

## 5. 运行行为

主操作固定为 `在本机运行`。只有所有必要检查器完成且整体状态为 `ready` 时才可点击；检查中、存在待办或系统准备失败时均不可开始。开始后系统：

1. 固定当前源码快照和配置；
2. 准备必要依赖；
3. 启动全部必要项目服务；
4. 检查进程、容器、端口和依赖；
5. 从每个本机公开访问地址连续验证。

底层支持逐服务启动、停止、重启和开发热加载，但这些属于运行后的次级管理能力，不占首次部署主线。后台刷新不得抢焦点、自动滚动或清空输入。

## 6. 成功依据

只有以下事实同时成立，才显示 `运行成功`：

- 实际运行的是本次选定的本地快照或仓库 Commit；
- 全部必要进程或容器仍在运行；
- 必要端口真实监听；
- 项目声明的必要依赖可连接；
- 全部必要内部服务健康；
- 每个公开服务的本机访问地址连续至少 3 次检查通过，相邻至少 5 秒、总窗口至少 10 秒。

结果必须展示：

- 主访问地址和其他公开地址；
- 源码身份；
- 实际进程或容器身份；
- 服务和依赖健康数量；
- 端口；
- 连续验证次数与时间。

项目没有声明健康接口或冒烟检查时，只能证明服务运行并可访问，不能宣称登录或其他业务能力正常。

证据当前有效期为 5 分钟。过期后显示 `上次验证通过 · 待复查`；打开已有部署时自动复查，离线时只保留历史事实和时间。

MVP 只支持至少包含一个 HTTP 可访问服务的项目。纯 CLI、Worker 和定时任务明确提示当前版本不支持。
